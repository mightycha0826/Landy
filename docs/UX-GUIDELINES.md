# Landy UX 가이드라인

> 휴대폰 한 손으로 쓰는 학생 앱의 **손맛 · 흐름 · 신뢰**를 지키는 규칙. 화면을 새로 만들거나 고칠 때마다 이 문서를 기준으로 삼는다.
> 규칙마다 **번호 · 수치 · 검사 방법**이 있다. "느낌상 괜찮다"가 아니라 재고 확인한다.
> 처음 작성: Phase 39 (2026-09-28). 규칙을 바꾸면 이 문서부터 고친다.

## 0. 우선순위와 원칙

충돌하면 위가 이긴다.

1. **안전** — 익명성 · 신고 · 되돌릴 수 없는 동작의 확인 ([README 설계 원칙](../README.md)이 최우선)
2. **흐름** — 하려던 일이 말없이 끊기거나 입력이 사라지지 않는다
3. **반응** — 누르면 즉시 무언가 일어난다
4. **즐거움** — 내 행동에 대한 보상감

다섯 가지 원칙:

- **P1 손가락은 커서가 아니다.** 누름 영역은 눈에 보이는 모양보다 넓어야 하고, 자주 누르는 것은 엄지가 닿는 아래쪽에 둔다.
- **P2 기다리게 하려면 보여 준다.** 100ms 안에 반응하고, 1초가 넘으면 무엇을 기다리는지 보여 주고, 실패하면 이유와 다시 시도를 준다.
- **P3 사용자의 작업은 사용자의 것이다.** 쓰던 글 · 찾던 상대 · 보던 위치를 앱이 멋대로 버리지 않는다.
- **P4 보상은 행동에 대한 것이다.** 즉각적인 반응과 축하는 좋다. 불안 · 압박 · 가짜 신호로 붙잡아 두지 않는다 (G8).
- **P5 요청은 공짜가 아니다.** Supabase 무료 한도(로그 1GB/월 ≈ 요청 1.3만/일)를 넘지 않는다. UX 개선이 요청을 늘리면 안 된다 (G13).

## G1. 누름 영역 · 배치

| 규칙 | 수치 |
|---|---|
| G1.1 모든 누를 것의 실제 누름 영역 | **44 × 44 px 이상** |
| G1.2 화면의 주요 버튼(찾기 · 보내기 · 저장) | 높이 **48 px 이상** |
| G1.3 서로 다른 대상 | 누름 영역끼리 **겹치지 않는다**(맞닿는 것은 괜찮다). 눈에 보이는 버튼 모양 사이는 **8 px 이상** |
| G1.4 되돌릴 수 없는 동작(삭제 · 차단 · 나가기 · 로그아웃)과 자주 쓰는 동작 사이 | **12 px 이상 또는 구분선**, 그리고 확인 단계 |
| G1.5 주요 동작의 위치 | 화면 **아래 1/3** (탭바 위 고정 · 입력창 옆) |
| G1.6 폼의 주요 동작 | 키보드의 이동/완료 키 — 모든 칸에 `enterkeyhint` (G6) |

**이렇게 넓힌다** — 겉모양은 그대로, 누름 영역만 44px로:

```css
/* app.css — .u-hit : 요소 가운데 44×44 의 투명한 누름 영역 (요소가 더 크면 요소 그대로) */
:where(.u-hit) { position: relative; }
:where(.u-hit)::after { content: ''; position: absolute; inset: min(0px, calc(50% - 22px)); }
```

쓸 수 없는 곳 (그때는 실제 상자를 키운다):

- `input` · `img` · `textarea` — 가상 요소가 없다. `label` 로 감싸거나 padding 을 키운다.
- 이미 `::after` 를 쓰는 요소 — `::before` 로 대신 (`.switch` 는 `::before` 를 쓴다).
- **이웃과 8px 미만으로 붙은 요소** — 뒤에 오는 요소의 가상 영역이 앞 요소의 보이는 부분을 가로챈다.
- 조상에 `overflow: hidden` 이 있으면 잘린다: `.g-card`, `.chat`, `.list`, `.sheet`, `.stories`, `Starters`.
- 문장 속 글자 링크는 예외 (WCAG 2.5.8 inline) — `data-hit-exempt` 를 달아 검사에서 뺀다.

**배치 원칙**

- 뒤로 · 닫기 · 메뉴(⋯)는 위 모서리에 둬도 된다 (자주 누르지 않고, 실수로 누르면 안 되는 것들이라서).
- 되돌릴 수 없는 동작은 메뉴 안쪽 · 시트의 아래쪽 · 구분선 너머에. "취소"는 항상 누르기 쉬운 자리에.
- 한 화면에 주 버튼은 하나. 두 개면 하나는 `.btn-ghost`.

**검사**: `npm run test:ui -- hit` (`scripts/e2e/hit.mjs`) — 360×740 · 390×844 에서 화면마다 보이는 모든 누를 것을 가운데 ±21px 네 점과 자기 상자로 찍어, 다른 요소가 잡히면 실패.

## G2. 누름 반응

| 규칙 | 수치 |
|---|---|
| G2.1 누른 뒤 눈에 보이는 반응 | **한 프레임(16ms) 안** |
| G2.2 글자 · 아이콘 버튼 (`.u-tap`) | 투명도 .55 (아이콘은 크기 .9), 들어갈 때 80ms · 나올 때 200ms |
| G2.3 카드 · 줄 · 큰 버튼 | 크기 .97 또는 배경색 |
| G2.4 처리 중 버튼 | 색을 유지하고 작은 스피너 — `aria-busy="true"` |
| G2.5 누를 수 없는 버튼 | 회색 `:disabled` — **처리 중에 쓰지 않는다** (꺼진 것처럼 보인다) |

- 전역에서 탭 하이라이트를 꺼 두었으므로(`-webkit-tap-highlight-color: transparent`) **`:active` 규칙이 없는 버튼은 눌러도 아무 반응이 없다.** 새 버튼에는 반드시 `.u-tap` 또는 자기 `:active` 를 준다.
- iOS WebKit 은 문서에 `touchstart` 리스너가 있어야 `:active` 를 그린다 — 루트 레이아웃에 passive 빈 리스너를 둔다.
- 누를 것에는 `touch-action: manipulation` (두 번 톡 확대 대기 제거). 끌기를 직접 처리하는 요소는 자기 값(`pan-y`, `none`)이 이긴다 — 그래서 전역 규칙은 `:where()` 로 둔다.

**검사**: 새 버튼마다 `:active` 스타일 유무를 리뷰에서 확인. 실기기(iOS)에서 한 번씩 눌러 본다.

## G3. 응답 시간 예산

| 걸린 시간 | 해야 할 일 |
|---|---|
| 0–100ms | 누름 반응 (G2) |
| 되돌릴 수 있는 쓰기 (공감 · 스위치 · 읽음) | **낙관적 반영** — 서버를 기다리지 않고 바로 바꾸고, 실패하면 **그 항목만** 되돌린다 |
| 300ms 넘게 | 버튼 안 스피너 — CSS `animation-delay: 300ms` 로 빠른 응답엔 안 보이게 |
| 1초 넘게 | 스켈레톤 (`.skeleton`, 실제 내용과 같은 크기 — 불러와도 화면이 튀지 않게) |
| 8초 넘게 | 무엇을 기다리는지 한 줄 ("연결이 느려요…") |
| 15초 | 시간 초과 → 실패 처리 + 다시 시도 |

- 보낸 메시지는 **바로 선명하게** 보인다. "보내는 중" 표시는 600ms 가 넘을 때만.
- 서버가 확정해야 하는 것(투표 · 나가기 · 신고 · 편지 보내기)은 낙관적으로 하지 않는다 — 대신 누른 버튼에 `aria-busy`.

## G4. 네 가지 상태

데이터를 보여 주는 **모든** 화면 · 목록은 네 상태를 가진다.

| 상태 | 보여 줄 것 |
|---|---|
| 불러오는 중 | 실제 모양과 같은 크기의 `.skeleton` + 화면 낭독기용 `sr-only` "불러오는 중…" |
| 비어 있음 | 이유 한 줄 + **다음 행동** (예: "새로 온 편지가 없어요 · 편지 쓰기") |
| 오류 | 원인 한 줄 + **다시 시도** 버튼 (44px). 토스트만으로 끝내지 않는다 |
| 오프라인 | 전역 알약 "오프라인이에요" — 화면마다 따로 만들지 않는다 |

- **네트워크 오류를 "없음"으로 보여 주지 않는다.** (예: 편지함을 못 불러왔는데 "편지가 없어요", 대화방을 못 열었는데 "대화를 찾을 수 없어요")
- 서버가 "없다/권한 없다"고 답한 경우(`not_member`, 잘못된 주소 `22P02`)만 "없음"으로 처리한다.
- **말없이 실패하는 곳이 없어야 한다.** `catch {}` 로 삼킨 오류는 화면 어딘가에 상태로 남긴다.

## G5. 탐색 · 뒤로가기 · 보존

| 규칙 | 내용 |
|---|---|
| G5.1 겹친 창과 뒤로가기 | 안드로이드 뒤로가기는 **맨 위의 닫을 수 있는 겹친 창부터** 닫는다. 창 하나 = 기록 한 칸 (`lib/overlay.svelte.ts`). 반드시 답해야 하는 창(`onclose` 없는 시트)은 기록에 쌓지 않는다 |
| G5.2 겹친 창을 닫으며 이동 | `navigateFromOverlay(url)` — `history.back()` 과 `goto()` 를 동시에 부르면 SvelteKit 이 한쪽을 취소한다 |
| G5.3 탭 이동 | 탭끼리는 기록을 바꿔 끼운다(`switchTab`). 탭마다 스크롤 위치를 기억한다 |
| G5.4 진행 중인 일 | 매칭 찾기는 탭과 잠깐 들여다보는 화면(알림 · 공지 · 설정 · 약관 · 업적)에서 이어지고, 그 화면에는 대기 막대를 띄운다. 쓰던 글이 있는 화면 · 다른 대화방으로 가면 멈추고 반드시 알린다. 찾는 동안 화면 꺼짐을 막고(`lib/wakeLock.ts`), 앱을 떠났다 오면 그동안 못 찾았다고 알린다 |
| G5.5 입력 보존 | 긴 글(편지 · 프로필 소개)은 **자동 초안** — `localStorage` · 24시간 · 사용자별 · 보내거나 로그아웃하면 지운다. 채팅 초안은 메모리(방마다) |
| G5.6 떠날 때 확인 | **하지 않는다.** `beforeNavigate` 는 사용자 정의 시트를 기다릴 수 없고, 알림 · 배너 이동에도 걸리며, 앱을 닫을 때는 브라우저 창이 뜬다. 자동 초안이 있으면 떠나도 잃는 것이 없다. "버리기"를 명시적으로 누를 때만 확인한다 |
| G5.7 알림으로 곧장 들어옴 | 뒤로가기가 앱을 닫지 않고 홈으로 간다 |
| G5.8 홈이 기록의 맨 아래 | 다른 화면에서 홈으로는 `goBack()` (새로 쌓지 않는다 — `lib/nav.ts`) |

## G6. 입력

- **G6.1** 모든 입력칸에 `enterkeyhint`(next · go · send · search · done), 맞는 `inputmode`, `autocomplete`.
- **G6.2** 로그인 칸은 앞부분만 받지만, `@cnsa.hs.kr` 까지 붙여 넣으면 도메인을 떼어 받는다. 다른 도메인이면 칸 아래에 알린다.
- **G6.3** 꺼진 주 버튼 바로 아래에 **무엇이 남았는지** 한 줄 ("이름을 적어 주세요 · 성별을 골라 주세요").
- **G6.4** 칸 오류는 입력을 마쳤을 때(blur)나 제출할 때 **그 칸 아래**에. 타이핑 중에는 빨간 글씨로 다그치지 않는다.
- **G6.5** 인증 코드 다시 받기에는 남은 초를 보여 주고, 시간이 되면 저절로 켜진다 (`S.now` 틱으로 계산 — `Date.now()` 는 반응하지 않는다).
- **G6.6** 글자 수 한도가 있는 칸은 한도의 90% 부터 남은 글자를 보여 준다. 한도 문구는 설정값(`msg_max_len`)에서.
- **G6.7** 키보드가 뜨면 입력창 · 보내기 · 토스트 · 시트가 키보드 위에 있어야 한다. 값은 `lib/keyboard.svelte.ts` 하나가 `<html>` 에 적는다 (Phase 41):
  `--vvh`(보이는 높이 — 화면 전체를 쓰는 창의 높이) · `--vv-top`(그만큼 내림) · `--kb`(아이폰에서 키보드가 가린 높이 — 아래에 붙은 것을 올림) · `html.kb-open`(탭바 숨김).
  화면마다 `visualViewport` 리스너를 따로 만들지 않는다. 안드로이드는 viewport 의 `interactive-widget=resizes-content` 로 화면 자체가 줄어든다.
- **G6.8** 입력칸 글자는 **16px 이상**. 아이폰은 16px 보다 작은 입력칸에 들어가면 화면을 확대하고 키보드가 내려가도 그대로 두어 화면 비율이 깨진다 (viewport 의 `maximum-scale=1` 도 같이 막는다).

## G7. 모션

| 토큰 | 값 | 쓰는 곳 |
|---|---|---|
| `--dur-press` | 80ms | 누르는 순간의 반응 |
| `--dur-1` | 120ms | 누름 · 작은 상태 변화 |
| `--dur-2` | 220ms | 색 · 투명도 · 작은 펼침 |
| `--dur-3` | 360ms | 화면 전환 · 일상 UI의 복귀 |
| `--dur-sheet` | 440ms | 바닥에서 올라오는 시트 |
| `--dur-exit` | 160ms | 작은 표면의 퇴장 |
| `--dur-sheet-exit` | 280ms | 시트의 퇴장 |
| `--ease-out` | `cubic-bezier(.2,.8,.2,1)` | 들어오는 것 |
| `--ease-in` | `cubic-bezier(.4,0,1,1)` | 나가는 것 |
| `--ease-settle` | 감쇠비 .82 · 주파수 12의 `linear()` 스프링 | 누름 복귀 · 시트 · 탭 표시 · 목록 정렬 (약 1% 오버슈트) |
| `--ease-spring` | `linear()` 스프링 (Badge 와 같은 곡선) | 튀어나오는 보상 (보냄 · 하트 · 배지) |

- **G7.1** 나가는 연출은 들어오는 연출 시간의 0.7배. 겹친 창(시트 · 고르기 · 알림 띠)은 모두 나가는 연출을 갖는다.
- **G7.2** 목록 등장 stagger 는 **8개 × 40ms** 까지 — 그 뒤는 한 번에.
- **G7.3** 1초가 넘는 연출(편지 봉투 · 매칭)은 **탭하면 건너뛴다.**
- **G7.4** 동작 줄이기(`prefers-reduced-motion`)면 모든 움직임을 끈다 — `app.css` 전역 규칙 + JS 연출은 `reducedMotion()` 확인.
- **G7.6** 물건을 흉내 내는 연출은 물리를 따른다 (Phase 40 봉인): 무게가 있는 것은 **예비 동작 → 빠른 충돌(ease-in) → 눌림(squash) → 되돌아옴**, 화면 앞에서 다가오는 것은 **그림자**가 가까워질수록 작고 진해진다. 부서지는 것은 조각이 사방으로 날아가기보다 금이 가고 붙은 쪽을 따라 움직인다.
- **G7.5** 새 곡선 · 시간을 인라인으로 만들지 말고 토큰을 쓴다.

**연결되는 움직임 (2026-10-04)**

- JS는 `lib/motion.ts`의 시간·곡선을, Svelte 표면 전환은 `lib/transitions.ts`를 쓴다. CSS의 `--ease-settle`은 같은 스프링의 샘플이다. `linear()` 미지원이면 `cubic-bezier(.16,1,.3,1)`로 복귀한다.
- 누름은 빠르게, 복귀는 차분하게. 평범한 탐색에 보상용 큰 탄성을 쓰지 않는다.
- 탭끼리는 순서(편지 → 채팅 → 프로필)에 따라 18px 이내로 이동한다. 선택 알약은 이전 위치에서 다음 위치로 이어진다. 하위 화면·뒤로가기는 계층과 실제 기록 방향을 따른다.
- 연속 탐색은 이전 View Transition을 건너뛰고 마지막 이동만 유지한다. 미지원 브라우저에서도 내용을 부드럽게 나타내며 페이지·초안·스크롤을 다시 만들지 않는다.
- 손가락으로 끄는 중에는 지연 없이 따라간다. 놓으면 현재 위치에서 복귀하거나 퇴장한다. 취소된 포인터·터치는 시트를 닫거나 새로고침하지 않는다. 던지기는 전체 평균 대신 마지막 이동 속도를 쓴다.
- 대화 기록은 등장 연출을 반복하지 않는다. 맨 아래를 보고 있을 때 새 마지막 메시지만 작게 올라온다. 이전 대화 읽기·불러오기는 보던 자리를 유지한다.
- 높이 전환은 답장 미리보기·작은 배너·입력칸에만 쓴다. 목록은 FLIP으로 정렬을 이어 주고, 긴 목록의 등장 지연은 280ms로 제한한다.
- 검증: `npm run test:motion` (곡선·방향·접근성), `npm run test:ui -- motion sheet react back` (실제 컴포넌트·드래그·뒤로가기). 두 종류의 동작 줄이기를 모두 확인한다.

## G8. 보상 — "도파민"은 이렇게

**허용 — 내 행동에 대한 즉각적인 보상**

- 보낸 말풍선이 튀어나옴 + 가벼운 진동
- 두 번 톡 → 하트가 터짐, 공감 배지가 튀어나옴
- 매칭 연결 · 편지 보냄 · 업적 달성 축하 (탭으로 건너뛸 수 있게)
- 매너 온도가 오르는 막대
- **정확한** 안 읽음 배지 — 보면 바로 지워진다

**금지 — 불안 · 압박 · 가짜 신호**

- 끊기면 잃는 연속 기록(스트릭), "오늘 안 들어오면…" 류 압박
- 끝없이 내려가는 피드
- 부풀리거나 가짜인 알림 · 배지, 재방문을 노린 무작위 보상
- 권한 · 평가 다크 패턴 (거절 버튼 숨기기, 닫으면 다시 뜨기, 거짓 "나중에")
- 같은 일로 두 번 축하하거나 **두 번 묻기** (예: 끝난 대화에서 평가하고 홈에서 또 평가 모달)

학생 대상 앱이다. 오래 붙잡는 앱이 아니라 **다시 오고 싶은 앱**을 만든다.

## G9. 햅틱 — `src/lib/haptics.ts`

| 함수 | 진동 | 쓰는 때 |
|---|---|---|
| `select()` | 8ms | 고르기 열림 · 하트 · 밀어서 답장 문턱 · 당겨서 새로고침 문턱 · 편지 봉인에 금이 갈 때 |
| `confirm()` | 12ms | 메시지 보냄 · 투표 · 저장 · 봉인 도장이 쿵 닿는 순간 |
| `success()` | [10, 40, 18] | 편지 보냄 · 업적 |
| `warn()` | [30, 60, 30] | 되돌릴 수 없는 동작 확인 |
| `match()` | 60ms | 매칭 연결 |

- `navigator.vibrate` 를 직접 부르지 않는다 — 이 모듈만 쓴다.
- iOS 는 Vibration API 가 없어 아무 일도 일어나지 않는다. **햅틱에만 의존하는 신호를 만들지 않는다** (항상 화면 반응과 함께).

## G10. 배지 · 알림

- **G10.1** 채팅 탭 배지 = `unread > 0 || !joined` 인 대화 **수**. 익명편지 탭 = 빨간 점(안 읽은 편지).
- **G10.2** 하트(알림) 점에는 채팅을 넣지 않는다 — 같은 것이 두 곳에 뜨지 않게. 하트 = 편지 · 공지 · 개인 공지.
- **G10.6** 알림 화면(하트)은 **한 목록**이다 — 공지 · 개인 공지를 따로 모은 화면이나 "공지 ·" 머리말을 두지 않고, 다른 알림과 같은 줄 모양으로 시간순에 섞는다 (Phase 40). 화면을 열면 공지는 본 것으로 저장하되, 연 동안은 "새 알림"에 남긴다. 개인 공지는 그 자리에서 펼쳐 읽는다.
- **G10.3** 보면 지운다: 대화방에 들어가면 그 방의 안 읽음 0, 공지를 열면 그 공지까지 본 것으로 (`markNoticesSeen(upTo)`).
- **G10.4** 앱 아이콘 배지(`setAppBadge`)는 지원될 때만 (iOS 16.4+ 설치 앱 + 알림 허용 / Android Chrome 미지원). 로그아웃하면 지운다.
- **G10.5** 푸시 권한은 **이유가 생긴 순간**에 묻는다 — 첫 대화가 끝났을 때, 첫 편지를 보내거나 받았을 때. 거절은 한 번이면 끝.

## G11. 토스트

- **확인 알림 전용**이고 2줄 이내 ("보냈어요", "복사됨"). 오류는 가능하면 원인 옆에 인라인으로 (G4).
- 한 번에 한 장 — 새 토스트는 같은 자리에서 바뀐다.
- 키보드가 떠 있으면 키보드 위에 뜬다 (전역 `--kb`).
- 토스트는 눌리지 않는다(`pointer-events: none`) — 그래서 "되돌리기" 같은 버튼을 토스트에 넣지 않는다.

## G12. 접근성

- 겹친 창은 포커스를 가두고 닫히면 연 버튼으로 돌려놓는다 (`lib/focustrap.ts`, 적용됨).
- 아이콘만 있는 버튼에는 `aria-label`.
- 상대의 새 메시지는 이미 `announce`(sr-only live)로 읽힌다 — "새 메시지 ↓" 알약에 `aria-live` 를 **또** 달지 않는다.
- 스켈레톤은 `aria-hidden` + 옆에 `sr-only` "불러오는 중…".
- 명도 대비 WCAG AA, 글자 12px 미만 금지(배지 숫자 제외), 새 모션은 G7.4.

## G13. 요청 예산

| 규칙 | 내용 |
|---|---|
| G13.1 | 새 폴링을 만들지 않는다. 필요하면 실시간 · 푸시 · `visibilitychange` 로 |
| G13.2 | 탭 화면에 **싱싱함 시간**(`FRESH_MS`)을 두어 탭을 오갈 때마다 다시 부르지 않는다 (`notices.svelte.ts` 방식) |
| G13.3 | 당겨서 새로고침은 그 탭의 로더만 — 앱 재부팅 금지. 10초에 한 번까지 |
| G13.4 | 낙관적 반영 뒤에 "확인용 다시 읽기"를 붙이지 않는다 |
| G13.5 | 요청 수는 `scripts/e2e/requests.mjs` 로 시나리오마다 센다. 늘었으면 이유를 적거나 되돌린다 |

현재 주기 (Phase 36 · 39): 하트비트 60s · 대화 목록 60s + 실시간 · 안 읽은 편지 2분 · 공지 5분(싱싱함 60s) · 업적 10분 ·
찾기 4s → 30초 뒤 8s → 2분 뒤 10s (백그라운드에서는 멈춤) · 대화방 안전 동기화 90s · 보고 있음 20s.

## G14. 코드 규칙 (UX 버그를 만드는 패턴)

- **G14.1** `$effect` 는 의도한 경우가 아니면 `page.url` · `page.state` 를 추적하지 않는다. 겹친 창을 뒤로 닫으면(얕은 기록) SvelteKit 이 `page.url` 을 **새 객체로 바꾼다** → 그걸 읽은 effect 가 다시 돌고 cleanup 이 실행된다. (Phase 39: 이 때문에 AI 대화를 닫으면 매칭 찾기가 멈췄다)
- **G14.2** effect 안에서 상태를 쓰거나, 상태를 읽고 쓰는 메서드(`seeker.start()` 등)를 부를 때는 `untrack` 으로 감싼다. (Phase 39: 끝난 대화에서 "새 대화 찾기"가 시작하자마자 멈췄다 · Phase 36: 업적 effect 가 하루 24만 번 요청)
- **G14.3** 겹친 창을 닫으면서 다른 화면으로 갈 때는 `navigateFromOverlay` (G5.2).
- **G14.4** 전역 상태(대화 목록 · 편지함 · 공지 · 찾기 · 초안)는 로그아웃 때 `resetSession()` 에서 비운다 — 같은 기기의 다음 계정에 보이면 안 된다.
